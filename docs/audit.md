## Критично

### К-1. Тома n8n и Ollama не защищены от `docker compose down -v`
`docker-compose.yml:82-85` — тома `n8n_data` и `ollama_data` объявлены обычными (managed). Имена совпадают с существующими (`n8n-stack_n8n_data`, `n8n-stack_ollama_data`), и данные подхватываются, но compose ими «владеет»: одна команда `docker compose down -v` удалит воркфлоу/креды n8n и скачанные модели Ollama безвозвратно.
**Фикс:** пометить оба тома `external: true` — тогда compose не сможет их удалить.

### К-2. Файлы логин-слоя не в git — сборка из чистого клона сломана
Не закоммичены (untracked): `web/default.conf`, `src/routes/auth.ts`, `web/src/stores/auth.ts`, `web/src/views/LoginView.vue`, тесты auth. При этом `web/Dockerfile:10` делает `COPY default.conf ...` — сборка образа из свежего клона упадёт, а nginx `auth_request` будет бить в несуществующий роут `/auth/check`.
**Фикс:** закоммитить весь слой аутентификации (коммитите вы сами — просто не забыть).

## Важно — баги и дыры в коде

### В-1. Протухшая сессия запирает пользователя в админке
`web/src/api/client.ts:23-39` — нет глобальной обработки 401; сторы не ловят её тоже. Гард `web/src/router/index.ts:20` зовёт `/auth/me` только один раз (`if (!auth.checked)`), после чего `authenticated` навсегда `true`. Когда cookie истекает: запросы в `onMounted` падают необработанным 401 без редиректа, а попытка зайти на `/login` руками редиректит обратно на `/` (гард считает вас залогиненным). Выход — только перезагрузка страницы.
**Фикс:** при `ApiError.status === 401` (кроме `/auth/*`) сбрасывать стор auth и уводить на `/login`.

### В-2. `POST /posts/:id/rewrite` не проверяет статус — «воскрешает» посты
`src/routes/posts.ts:156-164` → `src/ai/worker.ts:88-133`: единственная проверка — существование поста. Пере-рерайт поста в `rejected` вернёт его в `pending` (воскрешение удалённого), в `published` — тоже в `pending` (рассинхрон с фактически опубликованным сообщением).
**Фикс:** `assertTransition` перед постановкой в `processing` (разрешить из `pending`/`failed`).

### В-3. ИИ-воркер меняет статусы в обход валидатора переходов
`src/ai/worker.ts:15-18,40-43,55,67-83` — переходы `→processing`, `→rejected` (дедуп), `→failed`, `→pending` идут прямым `prisma.post.update`. Валидатор `src/status.ts` применён только в approve/unapprove/delete/published. Правило ТЗ «переходы валидирует сервис» (`PO-PLAN.md:112`) соблюдено наполовину; гонки (например, оператор удалил пост, пока воркер его обрабатывал) молча перетирают статус.

### В-4. `ADMIN_COOKIE_SECURE` не доходит до контейнера
`src/routes/auth.ts` читает `ADMIN_COOKIE_SECURE`, переменная описана в `.env.example`, но в `docker-compose.yml` в `backend.environment` её нет. При переезде админки за HTTPS флаг молча не сработает.
**Фикс:** добавить `ADMIN_COOKIE_SECURE: ${ADMIN_COOKIE_SECURE:-false}` в env бэкенда.

### В-5. `dotenv` не объявлен в зависимостях
`vitest.config.ts:8` подключает `setupFiles: ['dotenv/config']`, но `dotenv` есть только транзитивно в lock-файле. Обновление зависимостей может сломать весь тестовый прогон.
**Фикс:** `npm i -D dotenv`.

### В-8. «Загрузка своего файла» для картинок — несуществующая фича

Отступление осознанное (зафиксировано в плане фазы 3), но ТЗ и человекочитаемая дока не обновлены.

### В-9. Управление каналами через UI не задокументировано

## Минор — код и поведение

- **М-1. Логин в dev-режиме косметический.** Vite-прокси бьёт в `:3000` напрямую, минуя nginx — `/api` в dev полностью открыт. Плюс fail-open: при незаданных `ADMIN_LOGIN`/`ADMIN_PASSWORD` `/auth/check` отдаёт 200 всем (осознанный дизайн, но тихий).
- **М-2. Очередь публикации игнорирует `channels.active`** (`src/services/postService.ts:204-209`) — посты выключенного канала всё равно уедут в публикацию. Флаг из ТЗ (`PO-PLAN.md:52`) ни на что не влияет.
- **М-3. `pubDate` = 1970-01-01 при отсутствии `isoDate`** (`src/normalize/normalizeItem.ts`) — в очереди (сортировка ASC) такой пост станет первым; ломает ровный тайминг.
- **М-4. TTL превью — висячий механизм.** `PREVIEW_TTL_DEFAULT` объявлен в `src/config/env.ts:6`, поле `channels.previewTtl` хранится, но ни то, ни другое нигде не потребляется. Фронт спрашивает previewTtl в форме канала, а бэкенд его никак не использует.
- **М-5. `auth.ts` читает `process.env` напрямую**, мимо zod-схемы `src/config/env.ts` — несогласованность с принятым паттерном конфига.
- **М-6. Карта переходов — надмножество диаграммы ТЗ.** `src/status.ts:12-14` дополнительно разрешает `processing→rejected` и `ready_to_publish→rejected` (нужно для дедупа и soft-delete); прокомментировано в коде, но диаграмма `PO-PLAN.md:96-100` не обновлена.
- **М-7. Кнопки «Удалить»/«Пере-рерайт» видны для терминальных статусов** (`ApprovalActions.vue:26-31`) — для `published`/`rejected` бэкенд ответит 409, пользователь получит только тост об ошибке. Лучше скрывать/дизейблить по статусу.
- **М-8. Фильтры протекают между каналами.** Стор `posts.filters` — синглтон; при переходе в другой канал остаются `status/bucket/source/date` прошлого → «пустая выдача» без видимой причины (бакета может не быть в новом канале).
- **М-9. Мёртвая ветка фильтра по каналу** в `PostFilters.vue:36-47` — единственный потребитель всегда передаёт `hide-channel`; наследие удалённого `PostListView`.
- **М-10. `PATCH /channels/:id` неиспользуем из админки** — нет UI редактирования/выключения канала (тумблер `active`, правка бакетов/расписания). Эндпоинт и тесты есть, кнопок нет.
- **М-11. Тип `Post` на фронте неполон** — фактический ответ содержит ещё `guid` и `embedding`; `embedding` (большой JSON) гоняется по сети зря. Стоит исключать его из выдачи API.

## Минор — инфраструктура

- **М-12. README.md — одна строка.** Нет инструкции запуска (`npm run start`), списка портов/сервисов, требований к `.env`. Вся эксплуатационная информация — в комментариях compose и `scripts/start.mjs`.
- **М-13. Нет healthcheck у backend**, а `web.depends_on` без `condition: service_healthy` — до готовности бэкенда (включая `prisma migrate deploy`) админка отдаёт 502. Для `db` сделано правильно — повторить для пары backend→web.
- **М-14. nginx: нет `client_max_body_size`** — дефолтный 1m меньше лимита Express (2mb), крупный JSON срежется 413 раньше бэкенда. Также нет gzip и кеш-заголовков для хешированной статики `/assets/*`.
- **М-15. Runtime-образ бэкенда тащит devDependencies** (`Dockerfile:22` копирует полный `node_modules` из build-stage: typescript, vitest, prisma-CLI). Стоит `npm ci --omit=dev` отдельным слоем.
- **М-16. `web/.dockerignore` не покрывает `tests/` и `*.md`** — раздувает контекст сборки (на финальный образ не влияет).
