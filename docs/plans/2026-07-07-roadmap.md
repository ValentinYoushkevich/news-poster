# Дорожная карта: сервис аппрува и публикации постов

> Обзорный документ. Каждая фаза — отдельный детальный план в этой же папке, даёт работающий и тестируемый инкремент. **Все фазы 1–5 выполнены**; что осталось — см. блок в конце документа.

**Источник требований:** [docs/PO-PLAN.md](../PO-PLAN.md)

## Зафиксированные решения (развилки из раздела 9 ТЗ)

| Развилка | Решение |
|---|---|
| 1. Где эмбеддинг + смысловой дедуп | **Всё в сервисе** (ИИ-воркер, в транзакции). n8n — тупой сборщик. |
| 2. Перевод EN | **Один промпт «переведи+перепиши»** (один вызов OpenRouter). |
| 3. Хранение вектора | **Json + брутфорс** по косинусу (сотни постов/сутки — хватает). |
| 4. TTL служебного канала | Поле `channels.previewTtl` (минуты), глобальный дефолт **1440 (24ч)** через env `PREVIEW_TTL_DEFAULT`. |

## Технологический стек

- **Язык:** TypeScript (строгий режим), запуск через `tsx`, сборка `tsc`.
- **Бэкенд:** Node.js + Express, PostgreSQL + Prisma.
- **Тесты:** Vitest + Supertest; тестовая БД Postgres (docker-compose), truncate между тестами.
- **Внешние (по фазам):** Ollama (`bge-m3`, эмбеддинги), OpenRouter (рерайт), Telegram Bot API.
- **Фронт:** Vue 3 + PrimeVue + Tailwind + Vite.

## Разбиение на фазы

### Фаза 1 — Фундамент: БД, каналы, ingest ✅
**План:** `2026-07-07-phase-1-foundation.md` — выполнен
Prisma-схема (`channels` + `posts`), миграции, каркас Express, конфиг/env, сериализация BigInt, CRUD каналов, слой нормализации сырых айтемов, `POST /posts` (ingest) с дедупом по `(channelId, link)` → 409, `GET /posts` (фильтры+пагинация), `GET /posts/:id`, `PATCH /posts/:id`.
**Даёт:** n8n может слать карточки, они нормализуются и складываются в БД; есть чтение/правка и настройка каналов.
**Зависит от:** —

### Фаза 2 — ИИ-воркер ✅
**План:** `2026-07-07-phase-2-ai-worker.md` — выполнен
Асинхронный воркер `ingested → processing → pending`. Конвейер на карточку: эмбеддинг (Ollama `bge-m3`) → смысловой дедуп (косинус Json, 24ч, скоуп канала, в транзакции) → классификация бакета из `channels.buckets` → рерайт+перевод одним промптом OpenRouter (few-shot из `channels.rewritePrompts` per-bucket) → копирование в `final*`. Провайдеры за интерфейсом. Спец-путь `сво` (минимальный рерайт). Ошибка шага → `failed` + `aiError`. `POST /posts/:id/rewrite` (idempotent, async).
**Даёт:** карточки автоматически доходят до `pending`, готовы к аппруву.
**Зависит от:** Фаза 1.

### Фаза 3 — Telegram + аппрув ✅
**План:** `2026-07-07-phase-3-approve.md` — выполнен
Telegram-клиент (один бот, `BOT_TOKEN`), заливка превью в служебку (`SERVICE_CHAT_ID`) → `file_id`. Эндпоинты: `POST /posts/:id/images` (добавление своей картинки по URL), `PATCH /posts/:id/images/select` (выбрать/убрать), `POST /posts/:id/approve` (залить в служебку → `fileId` + `previewMessageId` → `ready_to_publish`), `POST /posts/:id/unapprove`, `DELETE /posts/:id` (soft-delete → `rejected`). HTML-экранирование `finalText`.
**Даёт:** человек через API аппрувит карточку и получает превью «как встанет в канал».
**Зависит от:** Фазы 1–2.

### Фаза 4 — Очередь публикации ✅
**План:** `2026-07-07-phase-4-publish-queue.md` — выполнен
`GET /posts/queue?channelId=&limit=` — очередь для публикующей джобы: массив `[{id, channelId, pubDate, caption, fileId, mainChatId}]` (ASC по `pubDate`, только каналы с `active=true`; `caption` — готовый HTML-экранированный текст), `PATCH /posts/:id/published` (`→ published` + `publishedMessageId`). Контракт с публикующей джобой n8n (per-channel расписание из `channels.schedule`, `sendPhoto`/`sendMessage` + фолбэк — исполняет n8n). Валидатор статусных переходов.
**Даёт:** публикующая джоба n8n забирает готовые посты и рапортует статус назад.
**Зависит от:** Фазы 1–3.

### Фаза 5 — Фронтенд-админка ✅
**План:** `2026-07-07-phase-5-frontend.md` — выполнен
Vue 3 + PrimeVue + Tailwind + Vite. Список карточек с фильтрами (`channelId/status/bucket/date/source`, пагинация), просмотр карточки, правка `finalTitle/finalText/bucket`, работа с картинкой (добавить/убрать/выбрать), кнопки «Заапрувить»/«Отменить аппрув»/«Удалить», показ превью.
**Даёт:** веб-интерфейс аппрува для человека.
**Зависит от:** Фазы 1–4 (API).

## Что осталось

- **n8n-воркфлоу не созданы** — ни сбор RSS, ни публикация. Реализован только REST-контракт бэкенда для них (`POST /posts`, `GET /posts/queue`, `PATCH /posts/:id/published`). Создание и экспорт воркфлоу в репозиторий — следующий шаг.
- Сверх исходных фаз уже сделано: аутентификация админки (`/login`, cookie-сессия, nginx `auth_request`), управление каналами через UI на главной странице, TTL-чистка превью фоновой джобой, docker-окружение с `npm run start`.
